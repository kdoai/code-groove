# 共有ルールを比較する検査

AIで機能を実装した後、コード全体の関係を把握できていない開発者を対象に、責務・共有ルール・変更の影響を調べます。重複やファイル数だけで問題とせず、具体的な変更負担、契約、反証、未確認事項を読みます。バグやセキュリティの網羅診断は行いません。

中心作業は、一つの実装を読みながら他の実装にも現れる共有ルールを短い音で比較し、変更時に合わせて調べる箇所と、残すべき境界を選ぶことです。音を外しても主要な成果・負担が変わらなければ、音を中心とした検査ツールとして成立したとは判断しません。音による効果は未測定です。

公開サンプルは[TSUGIAIの固定版](TSUGIAI_DEMO.md)です。checkout・返品は開発と回帰検証の作例であり、公開サンプルの代わりとして案内しません。TSUGIAIの保存結果で対応していない関係は、対応不足として表示します。

[TSUGIAIのセッション指定課題](TSUGIAI_SESSION_INSPECTION.md)では、元の記録を保持し、新しい実調査の未採用案を比較できます。5処理の初期化前提を1関係へ対応させ、周囲の回答保存・進捗・完了の役割は保持します。行の重なりだけを正しい音対応と扱わず、条件全体と実装所有者を照合しています。

## 操作と意味

「共有ルールを比較」は問題認定前から使えます。保存された根拠付きイベントの責務IDと意味キーが同じで、別の実装にある出現箇所を並べます。共通する下位ルールと周囲の役割を分けて読み、実装・根拠行へ移動できます。分類が違うルールを文字列や音の類似だけで統合しません。同じキーはAgentが対応付けた意味であり、条件式・数値・挙動の完全一致の証明ではありません。

比較用の識別フレーズは各2.5秒、同じ責務の固定8音・96BPM・一定の発音強度で、曲中位置・周辺イベント・曲末の変奏から独立します。A→Bは5秒です。これは保存された意味の識別用に生成する音で、元の演奏の抜粋や実行トレースではありません。意味キーの違いを音高へ追加で符号化していません。同じ責務内の異なるキーを音だけで識別できるとは主張しません。周囲の役割と処理は既存の文脈試聴で確認できます。

関係表示・根拠リンクは音なしでも同じです。未対応・未調査は問題なしを意味しません。閲覧・比較・質問の下書きでモデルは呼び出しません。質問を送信すると、認証・利用枠・予算・取消制限のある追加調査を開始します。

追加調査は、既存の根拠を読み直して仮説・反証を更新します。初回の意味イベントが不足している場合、既に調査済みの実装内に限り、根拠付きイベントの追加・置換を提案できます。完全な実装読取、出現範囲の根拠、件数・旋律上限、置換後の参照を検証します。新しい未調査の実装を分類済みに変える機能ではありません。範囲外は新規解析が必要です。

結果には追加・置換・再分類の内容を表示します。人が「調査結果を演奏に反映」を選んだ場合だけ、新しい解釈と譜面を保存します。元の記録とソースは保持し、対象リポジトリへ変更・pushしません。

## checkout開発課題

[評価セットの草案](../evaluations/checkout-quantity-v1.json)は自作の開発用題材です。人による確認待ちで、独立した正解集合ではありません。

対象商品の数量合計2以上という条件を追加します。数量はギフトカード以外の明細のquantity合計です。請求・特典・プレビューを確認し、呼出元・型・説明・テスト・外部利用も調べます。ポイント率は維持しても、割引後の商品金額が変われば付与ポイント数は変わり得ます。数量不足の表示契約を決め、変更が必要な箇所と確認だけ必要な箇所を区別します。オフラインと提出時刻判定、出力形式、永続化境界を維持します。共通純粋ルール、生成/version管理、明示的に同期管理する別実装を別解として扱います。

~~~powershell
uv run python scripts/evaluate-shared-rules.py
~~~

このコマンドは保存済みv6解析のソース・読取hashを確認し、期待範囲に重なるイベントと共通キーを報告します。対象コードの実行、新規モデル呼出、意味の自動正解判定はしません。範囲の重なりは意味の一致を証明しません。元の記録は変更しません。

## 評価と公開する限界

M0: 対象作業と成功条件を定義。M1: 人が正解・別解・保留条件を確認。M2: 現行Agentと通常AIレビューを同じ入力・検索手段・予算で反復評価。M3: 確認した失敗だけを改善し未使用題材で再評価。M4: 同じ診断・根拠・操作を使い音の有無だけを比較。M5: 実測に応じて機能と説明を整理します。

人の評価では、診断文に答えが直接書かれていない別の変更課題を使い、見落とし・誤判断・境界を残す理由を主評価にします。時間・操作・主観負担には練習と再生も含めます。課題と順序を入れ替え、最小効果・許容誤判断増加・試行数・保留条件を事前登録します。診断を隠したり音なし画面を不便にしたりしません。

現在の状態: 保存済みの取りこぼしは確認済み。現行v14の新規比較評価、人の評価セット確定、未使用題材での反復評価、旋律の知覚的識別性、音による判断・負担への効果は未実施です。契約・音の安定性・ブラウザ操作の技術テストは、これらの効果を証明しません。ライブテストは明示依頼時だけ行います。

[保存済みv6の表現検査結果](../evaluations/checkout-representation-v1.json): 対象商品の抽出、適用判断、割引計算の三関係はいずれも三実装共通のキーがありません。適用判断・割引計算は三範囲にイベントが重なりますが、上位の役割ごとに別分類です。意味の再現率や現行Agentの失敗率ではありません。
