# 音とコードの対応

Code Grooveは、コードの責務と処理の関係を音とタイムラインに表します。音を選ぶと、対応するコードの範囲とAgentの説明を確認できます。

## 二つの並び方

ファイル順の表示では、同じ責務がどのファイルに現れるかを追えます。意味ごとの表示では、関連する処理をまとめて確認できます。両方の表示で、音が指す根拠コードは共通です。

同じ責務には同じ旋律を使います。一つの関数に複数の責務がある場合は、それぞれの旋律が現れます。ベースと和音は演奏の背景で、コードについての判断を表しません。

タイムラインの小さな丸印から、確認候補の根拠コードと保存された説明を開けます。観察した違い、Agentの解釈、別の説明とその確認状態、未確認事項を区別して読みます。理由のある違いや判断保留も同じ入口から確認できます。責務の色を警告色へ変更しません。

## 追加調査の結果

選択した範囲を追加調査すると、根拠のある指摘を保存できます。利用者が結果を反映した場合、指摘に対応する短い応答を演奏へ加えます。

| 指摘 | 音の表現 |
|---|---|
| 同じ判断が複数箇所に分散している | 離れた箇所で同じ応答を繰り返す |
| 一つの処理に複数の責務が混在している | 異なる旋律が交互に応答する |
| 変更時に複数箇所を合わせる必要がある | ずらしたリズムで応答する |
| 処理の流れを追いにくい | 区切られた旋律で応答する |

正当な境界と判断した場合や根拠が足りない場合は、指摘の応答を加えません。音がない箇所にも、未調査のコードが含まれます。

## 再生

現在の演奏は`groove-chamber-v10`と`midnight-jazz-v4`の音源を使います。テンポは96 BPMで、ドラムは使いません。コードに対応する音がある小節をつなぎ、小節内の休符とリズムを保ちます。

保存済みの解析を再生するときは、新しいモデル呼び出しを行いません。同じ解析と音源から同じ楽譜を作りますが、端末や音声出力の違いで実際の再生タイミングは変わることがあります。

現在位置には、発音中の責務・実装・根拠行を表示します。コードの自動追従を外して別の根拠を読んでも、演奏位置は区別して表示し、「演奏位置の根拠へ」で一時停止して戻れます。試聴中は短い試聴の発音位置を表示し、全体演奏の位置は保持します。音のない間は閲覧中の根拠を表示します。演奏順は譜面上の配置で、コードの実行順・実行進捗ではありません。

伴奏を外すときは、共通のベース・和音を除き、コードの根拠に結び付いた責務の旋律を残します。旋律は責務の識別用、意味イベントの打点は保存された処理の位置を示します。識別用の旋律の反復を、コードの実行回数や欠陥の証拠とは扱いません。

確認候補の試聴は、関連する実装のフレーズと周辺の処理を取り出します。「何を聴き比べるか」にA・Bの実装、責務、旋律と打点、根拠行を表示し、実装を選び直せます。各最大4小節（10秒）、A→Bは最大20秒です。確認ポイントの付近を同じ小節数・テンポ・音量で聴き、元の音高・打点の強さ・小節内の間隔を保ちます。省略した小節・範囲外の確認ポイントを表示し、未調査の箇所には音を補完しません。

保存された責務・意味キーの対応が一意でない箇所は対応不明です。値・条件・共有状態の安全性など、音に反映されない違いはコードと説明で確認します。「責務の混在」という候補でも保存結果が単一の責務に分類されている場合、異なる旋律では確認できないことを示します。比較の参加者を並べる順序は実行順ではありません。

短い側の末尾に長さを揃える休符を置く場合は、その小節数を表示します。比較のための休符であり、元コードの処理間隔を表すものではありません。

選択区間の短い試聴も、対象実装の責務の旋律と周辺の処理を最大4小節取り出します。対象外の小節は省略します。試聴終了・取消・読込エラー・表示範囲の切替では、元の譜面と再生位置・設定へ戻り、一時停止します。音なしで根拠を読む操作も維持します。

二関数を同条件で聴く手順は[比較の説明](STRUCTURE_COMPARISON.md)、呼出・返却・利用を読む手順は[静的な関係の説明](CALL_RELATIONSHIPS.md)を参照してください。反証を調べた記録も、欠陥の確定や人の承認を意味しません。

音はコードを探し、関係を比較するための手がかりです。設計の妥当性やバグの有無は、根拠コードと説明を読み、必要なテストを行って判断します。
