# 音と意味の対応 — chamber-v10

Geminiは音楽を生成しません。検証済みSemanticMapを`packages/groove-core/src/compiler.ts`が固定規則でScoreBundleへ変換します。96 BPM・4/4、六つの責務モチーフ、最大32小節／sceneです。伴奏は共通の音楽で、判断根拠はありません。

責務内の意味キーをsemantic_order順の初出で八つの音高スロットへ割り当てます。同じ責務＋concept_keyは同じ音高・音色になります。九つ以上のキーは循環するため、同じ音高だけで意味が同じとは判断できません。発音位置は意味の順番とRepo／Theme配置に基づき、同じ音高でも位置や長さが異なる場合があります。

比較教材`recorded-returns-before`では、返品期限・対象商品・手数料の三つのキーが店舗とWebの別ファイルにあります。画面に対応する音高と行番号を表示し、短い聴き比べでは伴奏を一時的に消します。保存済み解釈は旧prompt-v3で生成された教材記録です。新たにGeminiが確認した結果ではありません。

R16の主デモは実在するTsugiaiです。51ファイルの参考コードと、9実装の保存済み意味譜面を分けます。懸念候補を破線と根拠行で示し、選んだ判断の打点を伴奏なしで最大10秒聴けます。元の意味ノートを使い、反証未確認の候補に新しい懸念音を付けません。文法・音高・スコアhashは変更しません。演奏の再開でコード追従が有効になり、発音中の根拠行がハイライトされます。

懸念のリズムには、根拠付きの比較対象と判定に加え、競合する説明を読取根拠で検討して棄却した記録（counter_status=rejected）が必要です。人の未回答事項・判断保留・反証未確認に警告音を付けません。旧解析の懸念の文章は保持し、確認記録がないことを明示します。根拠付きイベントがゼロなら空の譜面として保存し、画面で演奏できない理由を示します。無音は健全性ではありません。

v9からv10への更新は音高割当と懸念音の成立条件を変え、AIのmap・sources・traceは保持します。文法・キットを含むハッシュを変更します。同じmap・文法・キットからの譜面再現と、新しいGeminiの判断再現は別です。

自動検証は意味イベント／音／根拠の保存、対応する音高、決定性、有限・非無音・非クリッピングを確認します。聴きやすさや発見速度は人による評価が必要です。[評価方法](acceptance.md)を参照してください。

## 構造比較 — structure-neutral-v1

意味譜面とは独立した構文音です。Agentの説明を読んだ人が二関数を選び、構文の配置を比較する補助に使います。欠陥・深刻度・品質・実行順は表しません。未抽出の情報を音で発見できるとは主張しません。

ブロック57、宣言・代入60、分岐62、反復59→59、return/throw65を中立音色で表します。値・式はコードで確かめます。A/B共通の呼び出し辞書はキーをソートし、55→67、67→55、60→64、64→60の最大4フレーズを割り当てます。初出順・A/B反転では変えません。静的同一参照先と「同じ呼び出し式・実行時の参照先未解決」を区別します。4種類超過では再生停止理由を表示し、コード・記録は使えます。衝突や別方式への自動切替はありません。

対応イベントなし、不明、未対応を同じ音色・強さの1/2/3打で区別し、判明したイベントの基本フレーズを残します。中立な差マーカー72は任意で外せます。既知の差への注意と、並びを聴くフレーズは別です。未回答に音は付きません。同じフレーズは同じ意味・動作の証明ではありません。

共有辞書・規則・音源版・元ハッシュ・比較と譜面からSHA-256を生成します。同じ入力では同じ譜面です。一区間12対応行、1行480ms、A/B間400ms、末尾200msで最大12.12秒。全行を連続区間に分け、手動で次へ移ります。反復回数の推定、切捨て、高速化、自動次区間はありません。音源失敗後もコード比較と記録を使えます。音の有用性・聞き分け・AIの見落としを補う効果は人による検証未実施です。
