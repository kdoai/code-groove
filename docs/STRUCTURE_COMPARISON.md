# 構造を比較して聴く — R15

Agentの調査／保存済み実解析を開き、役割、関係、根拠、未確認事項を読みます。人が二関数を選んで構造とコードを比べ、任意で聴き、期待・観察・疑問を記録します。追加調査は明示操作だけで開始し、回答を読んで人が理由の確認状態を更新します。静的抽出はこの流れを支える読取道具です。AIの懸念や意味イベントにない構文も選べます。

## ローカルデモ

本番はローカル専用モック操作を表示しません。公開の実解析サンプルでは、ログイン後の明示追加調査が先に自分の私有コピーへ保存し、その解析IDへ依頼します。比較画面と独立記録は継続し、「保存した自分のプロジェクトを開く」で保存先へ移れます。同じ画面内の再依頼は同じ保存先を使います。模擬教材は本番では比較・記録・書き出しに使い、新しい実モデル解析は開始しません。

1. `pnpm build:tools`、`uv run uvicorn code_groove.app:app --app-dir apps/backend --port 8080`、別端末で`pnpm dev:web`。既定のfixture/localを使い、実モデル設定を有効にしません。
2. 保存済み実解析の返品教材を開き、Agentの説明を読みます。「Agentの説明を二関数で問い直す · 構造を比較して聴く」を押します。
3. A/Bの任意関数を選び、左右コードと構文対応を確認します。「音を使う」を外しても、構造行からコードに移動し、期待／観察／疑問を記録できます。
4. A、B、A→Bを短く再生し、停止します。区間は手動で進め、対象行と残りを確認します。共有辞書の呼び出しフレーズはA/Bで同じです。
5. 疑問を入力し「モック追加調査を試す（ローカル専用）」を押します。両関数を静的に読み直した根拠付きの**モック回答**です。元の保存済みGemini実解析とは別表示・別JSONです。モデルは呼びません。
6. 確認状態を人が更新し、「ローカルJSONに書き出す」。開始／終了、操作時刻、選択範囲、コードhash、解析の生成元、規則版、辞書、音源版、譜面hash、音の設定、メモ、状態、回答と読取根拠を保存します。終了は「今回の記録を終了する」で明示記録します。
7. 材料を「短い比較教材（模擬）」に替えるとconstantA/B、loopA/B、addedA/B、orderA/B、directA/extractedB、branchA/B、intendedA/B、unknownA/Bがあります。順序例はcheck/save/notify/auditの4呼び出し。意図された定数差と、仕様不足の差を別に説明します。新教材を実Geminiの見落とし例と呼びません。

## M0 — 独立した契約

`schemas.py`が正本でJSON Schema／TypeScriptを生成します。SyntaxProjection、StructureComparison、StructurePlaybackPlan、ComparisonHumanRecord、ComparisonInvestigationRequest/Result、ComparisonExportを追加します。MeaningEvent、ReviewSignal、ScoreScene、AI証拠を捏造せず、既存の意味譜面は変更しません。

## M1 — 中立な構文音

structure-neutral-v1／sorted-call-pairs-v1／sine-envelope-v1。最大4種類の呼び出し先／式をソートして共有辞書にし、A/B反転でも同じフレーズです。静的参照先と未解決の「同じ呼び出し式」を区別します。5種類以上は音だけ利用不能と明示します。値や式の正確な差はコードに戻ります。差マーカーは独立した任意設定です。空き・対応不明・未対応は中立音の個数と配置で区別します。12行ごとの連続区間、最大12.12秒／A→B。切捨て・高速化・自動次区間はありません。音の仕様は[SONIFICATION.md](SONIFICATION.md)。

## M2 — 抽出と対応

導入済みTypeScriptパーサーを使い、.ts、160行未満、16,000文字以内、512イベント以内を対象にします。スナップショットID、SHA-256、静的索引の関数ID、元行／列／UTF-16オフセット、親、深さ、分岐所属、構文配置順を保持します。Python／TSXの既存解析は維持し、新しい構造比較は対象外と示します。

分岐、反復、呼び出し、宣言／代入、return／throw、ブロック、条件／右辺／引数のASTを保持します。入れ子関数とコールバックは別単位で、親は境界だけ表示します。呼び出し先を展開せず、反復回数や実行順を推測しません。コメント・空白・改行だけを除去し、名前、プロパティ／文字列キー、定数、演算子、引数、参照先を保持します。30とMAX_DAYS、直接処理とヘルパー、ifと三項／早期returnを意味的に同一扱いしません。

名前正規化は後回しです。将来も確定した束縛への参照だけを正規化し、外部名・プロパティキー・文字列キーを保持します。短縮プロパティはキーと値参照を分け、不明なら変えません。`{ amount }`と`{ total }`の返却キー差を消しません。

unique-monotone-v1は一意な正規化構文一致を足掛かりにし、逆転する足掛かりを採用しません。両側の順序を保存します。同じ形の単一候補区間は「異なる」、複数候補は「対応不明」、信頼できる足掛かりの片側空きは「対応イベントなし」。未対応構文、解析失敗、対象外、空の正常結果を分け、元コードと診断へ戻れます。部分の空きは関数全体の処理欠落の断定ではありません。構文一致は意味や動作の一致を表しません。

## M3 — 人の問いとAgent

`POST /analyses/{analysis_id}/comparison-investigations`はscene_idを要求しません。同じスナップショットの二関数、hash、比較行範囲、期待・観察・疑問、初回解釈を渡します。所有者、期限、最新解析、同一コード版、範囲を受付とworkerで検証します。選択関数を両方読み直した今回の根拠がなければ提出できません。既存の単一ADK bounded loop、20ツール、180秒、160k/20k予約、追加調査10件/UTC日、全体予算、取消、lease、CASを再利用し、上限を広げません。

結果は初回説明を維持／修正／保留する理由、競合する説明、未確認事項、今回の根拠を返します。既存の意味解析結果と別に関連付け、構造回答をScoreSceneに採用する入口は拒否します。ソース変更・裏の自動解析・自動連鎖はありません。ローカルモックは明示したfixtureで、実際の静的読取／提出ツールを通し、モデル・有料ジョブ・予算を使いません。

## M4 — 記録と操作

左右コードは読取専用。構文行のボタンと再生中の項目から、両側の元位置を強調します。キーボードと音なしで操作できます。差の認識（未記録／認識した／認識できなかった）、理由確認（未着手／未回答／判断保留／根拠付き確認）、人の判断（未記録／意図された差／要検討／前提不足）、操作履歴を分離します。根拠欄と人の明示選択だけが確認済みの記録になります。再生、表示、AI回答はメモや状態を消去・完了しません。

端末のlocalStorageで比較ID／元hash／行範囲ごとに保持し、analysis_idやAgentPanel再マウントとは独立です。切替や回答受信で失いません。新しいコード版の判断には転用しません。書き出しには実際の操作時刻だけを含めます。クラウドでのメモ永続保存、複数端末共有、記録のインポートは初版外です。

## M5 — 検証と制限

検査結果は`EXECUTION_PLAN.md` R15欄に記録します。モックAPI／Agent loop／E2Eは実モデル精度を証明しません。音の有用性、聞き分け、AI見落とし補完効果は人による検証未実施で、今回の完了条件に含めません。参加者募集・比較実験・liveモデル・配備・push・公開は行いません。

一般的な大規模比較、Python／TSX構造対応、言語間比較、意味同値推論、候補推薦、全体網羅、辞書拡大は保留です。比較内で抽出・表示した論点を考える入口が初版の到達点です。
