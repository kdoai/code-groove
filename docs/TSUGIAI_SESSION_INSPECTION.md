# TSUGIAIの対象セッション指定を検査する

対象はTSUGIAIの固定版 `35a951488d7b00518e7e73a329d46713cbeacbe8` です。公開サンプルの題材を変えず、元の保存済み解析を保持したまま、同じ9実装の新しい調査を別版で比較します。対象コードは実行・変更しません。

## 変更課題

対象セッションを呼出ごとに明示できるようにする。写真依頼の戻り値と、Phase3の完了経路は維持する。

これは仮想的な変更の影響を調べる開発課題です。同時実行の障害を発見・再現したという主張ではありません。共通しているのはセッションの前提契約で、すべての処理が同じ業務責務であるという意味ではありません。

## モデル出力の前に作成した評価表

[機械可読の評価表](../evaluations/tsugiai-session-explicit-v1.json)は、固定ソースを照合して作成したAgentによる草案です。独立した人の確認をまだ受けていないため、一般的な精度や正解率の根拠には使いません。

公開時にソースハッシュの記録形式だけを「パス・SHA-256」の配列へ変更しました。実行前の原本ハッシュと改行形式を残し、元の評価表を再構成して同一になることを検証しています。期待結果と全ソースハッシュは変えていません。

| 確認する対象 | 根拠 | 期待する判断 |
|---|---|---|
| 回答保存・保留追加・項目完了・進捗取得・チェックアウト完了 | `agents/checkout_agent/tools.py` の5つの初期化ガードと、それぞれのセッション参照 | 対象セッションとサービスの束縛を一緒に確認する。周囲の保存・集計・完了という役割は区別する |
| 初期化と呼出側 | `tools.py:7–23`、`agents/main.py:466–477,557–602` | セッションIDだけでなく要求のテナント別サービスとの対応も確認する |
| Agentへのツール登録 | `agents/checkout_agent/agent.py:122–154` | 明示的引数・束縛済みツールのどちらでも、呼出契約を確認する |
| 写真依頼 | `tools.py:94–113` | 共有参照を読まない反例。全ツールが直接依存するという仮説を修正する |
| Phase3の完了境界 | `tools.py:189–216`、`agents/main.py:1263–1318` | Agentツールによる完了と、専用APIによるPhase4・pending_reviewへの移行を混同しない |
| 永続化サービス | `agents/services/firestore.py:130–146` | 既にsession_idを受け取る下位契約と、上位の対象指定を区別する |

要求ごとの引数と、要求ごとの束縛済みツール／コンテキストを妥当な別解として扱います。呼出元・テナント境界が未読なら保留します。実行時の隔離、文書・テストの網羅性は静的な読取件数から保証しません。

## GCPでの比較手順と費用

現在のconductorプロンプトを変更せず、Gemini 3.8 FlashをGCPの `artful-bonsai-491601-p3`、globalエンドポイントで使います。51ファイルの同じ読取範囲、同じ変更課題・読取ツール・トークン上限を与え、現行Agentと一般的なAIコードレビューを3回ずつ交互に実行します。通常レビューは自由記述、現行Agentは構造化提出と根拠検証を使う点が異なります。成功回だけを選びません。

~~~powershell
uv run python scripts/tsugiai-session-evaluation.py prepare
uv run python scripts/tsugiai-session-evaluation.py current --name current-1 --execute-paid
uv run python scripts/tsugiai-session-evaluation.py baseline --name baseline-1 --execute-paid
~~~

モデル利用は明示した有料実行だけで開始します。実行名の再利用を拒否し、結果・失敗・読取記録・トークンを `.local/tsugiai-session-evaluation` に残します。失敗した実行も最大費用の予約を保持します。既存台帳を消して再実行すると累計管理を失うため、消さずに使います。

許可されたAI予算は5,000円です。実行側は合計4,000円を上限とし、1ドル250円、10%の余裕、入力100万トークン2ドル・出力10ドルという保守的な係数で実行全体を事前予約します。これは実請求や実勢為替ではありません。[Google Cloudの料金](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing?hl=en)と実トークンに基づく見積もりは別に記録します。

## 音と人の判断

同じ前提契約の各出現を同じ意味キーで比較できるかと、その表現が人の判断を助けるかを分けます。初回解析にない対応を手で音へ足して、Agentの発見として扱いません。追加調査の新しい読取と検証済みの提案を別版に残し、人が内容を確認してから比較します。

人の課題は「確認する実装、写真依頼を除く理由、Phase3の境界、保留すべき事項を根拠付きで説明する」です。音あり／なしで同じ説明・関係表示・根拠を用意し、見落とし・誤判断・根拠への到達時間・練習と再生を含む時間を記録します。この一件で答えを覚えた後の再試行を、音の効果の証拠にはしません。実参加者による比較が終わるまでは効果未測定とします。

## 画面で最後まで進める

1. 評価表と、現行Agent・通常レビュー・失敗した追加調査の結果を読む。
2. 写真依頼とPhase3の根拠を確認し、「追加調査案を比較用に開く」を押す。これは未採用案の試聴で、サーバー上の解析やソースを変更しない。
3. 5処理からA・Bを選び、共通の短い識別フレーズと周囲の役割を比較する。音・根拠リンクから該当行へ戻る。
4. 音を切っても同じ関係と根拠を読める。途中で音を切り替えた場合、判断記録は `mixed` とし、音なしの試行と偽らない。
5. 確認する実装・残す境界・未確認事項を自分で記入し、判断を端末に保存またはJSONへ出力する。

人の判断は自動記入しません。ブラウザの操作テストの入力は実参加者の評価に数えません。評価表の人による確認、未使用題材の診断評価、音の識別性と比較試行は残っています。
