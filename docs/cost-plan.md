# 費用と利用上限

インフラの予算目標は月額6,000円です。AIの利用料金は別に管理します。保存済みのデモ再生ではモデルを呼び出しません。

## インフラ

東京リージョンのCloud Runを使い、最小インスタンス数を0に設定します。

| サービス | CPU | メモリ | 最大インスタンス数 |
|---|---|---|---|
| Web・API | 1 vCPU | 512 MiB | 2 |
| 解析worker | 1 vCPU | 1 GiB | 1 |

Cloud Tasksの同時実行数は1です。Firestore、Cloud Storage、ビルド、コンテナの保存、通信にも利用量に応じた費用がかかります。

予算の50%、80%、100%で通知する設定を使います。予算通知やインスタンス数の上限は、請求額の上限を保証しません。実際の利用量と請求を継続して確認します。

## AI解析

日次の解析上限は1ユーザー10回で、日本時間09:00に切り替わります。同じユーザーによる解析の同時実行は1件です。追加調査には別の回数枠があります。

各要求でトークンを予約し、全体の入力・出力トークン上限も確認します。管理者は解析を停止できます。料金設定を確認できていない場合は、金額の見積もりを表示しません。

モデルはGemini 3.8 Flashを維持します。上限の正本は`apps/backend/code_groove/agent_limits.py`です。ジョブ作成時に同じ上限を予約・保存し、workerとAgentがその保存値を使います。変更前に予約されたジョブは従来の予算と時間を維持します。

| 1ジョブの上限 | 新規解析 | 追加調査・改善案 |
|---|---:|---:|
| 累計入力トークン | 1,200,000 | 480,000 |
| 累計出力トークン（推論含む） | 96,000 | 64,000 |
| 1要求の入力トークン | 144,000 | 144,000 |
| モデル要求 | 18回 | 12回 |
| ツール | 100回 | 100回 |
| 全体の時間 | 480秒 | 360秒 |

モデルHTTP応答は120秒まで待ち、ジョブの残り時間が短ければそちらを優先します。システム指示と実際に送るツール定義もCountTokensへ渡し、文字数からの推測を加算しません。[GoogleのCountTokens仕様](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/models/count-tokens)

入力、出力、モデル要求、ツール、時間の余裕から探索を閉じ、最終提出・修正の枠を残します。一つの応答に多くの読取が含まれても、提出用のツール枠を使い切らせません。読めなかった実装は未調査として提出できます。ただしモデルが有効な候補を提出しない場合、入力自体が収まらない場合、接続・権限・サービス障害では失敗を明示します。失敗・再試行の予約を取り消して上限をすり抜けません。

日次の全体入力3,000,000・出力300,000トークン、同時実行数、利用回数枠は維持します。各ジョブの最大額を先に予約するため、日次枠の残量によっては10回より前に受付を停止します。

リポジトリは最大500ファイル・4 MiBを取り込み、原則24実装以内・読取回数の見積りに応じて分割します。全体を一度のモデル要求へ送る設計ではありません。関連コードの読取や一つの巨大な実装では、分割後でも上限に達する場合があります。保存済みの分割結果を再利用して、未調査の範囲を明示的に続けます。

[TSUGIAIの変更課題](TSUGIAI_SESSION_INSPECTION.md)の有料評価は通常の利用枠とは別の明示実行です。合計5,000円の許可に対し、実行側は保守的な最大費用の予約合計4,000円で停止します。公開検査の閲覧・試聴・判断保存では新しいモデル要求は発生しません。

## 保存期間

私有プロジェクトは作成から7日後にアクセスできなくなります。保存物はライフサイクル設定に従って物理削除します。削除要求を受けた場合は閲覧を直ちに拒否し、削除処理を予約します。
