# 運用・審査再現手順 — R16

公開サンプルと私有コピーを区別します。公開サンプルは固定map・source・trace・文法・音源で再生でき、私有projectの7日アクセス期限に依存しません。公開サンプルを所有コピーへ保存しても、新規AI解析にはなりません。

## 提出する版を固定する

提出候補のGit SHA、lock、コンパイラ文法、kit hash、サンプルscore hash、配備revision、動画SHA-256をrelease記録へ保存します。公開URLでTsugiai主デモ→51ファイルと未解析表示→コード追従→懸念候補の根拠行と伴奏なし試聴→反証状態→未ログインの質問とログイン要求を確認します。音の比較教材は別サンプルです。POSTによる解析要求なしで再現することを確認してください。

公式ルールでは提出後の内容を変更せず、2026-12-01まで配備を維持します。提出後は主サンプルや文法を差し替えず、サービス障害に対して同じSHAへロールバックします。私有コピーを一律長期保持することで再現性を作りません。審査の新規解析用アカウントと予算は非公開の手順で管理します。

## 障害・停止

実解析を止める場合は既存のruntime control kill_switchまたはENABLE_LIVE_ANALYSISを使います。保存再生は継続できます。失敗したliveの代わりにfixtureを返しません。Cloud Tasksのlease・retryとAPIの実行状態を照合し、二重ジョブを手動で作りません。

画面を閉じてもジョブは続きます。同じアカウントで開き直し、global Agent activityから進捗を確認します。期限切れ／削除状態ではコードと結果へのアクセスを拒否します。

## 費用・配備前チェック

東京、min=0、web max=2／worker max=1、Tasks同時実行1、private workerを維持します。Firestoreイベントpollは新しいseq範囲だけを読取ります。AIの予約・清算、全体token上限、日次10回を確認します。予算アラートは自動停止ではありません。
