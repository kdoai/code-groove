# 提出用ドラフト

Code Groove — コードの設計を聴き、根拠をたどるレビュー・ワークスペース。

対象は、TypeScript・Pythonプロジェクトを理解する開発者やレビュー担当者です。「同じ仕様変更で別のファイルも直す必要がある」「似て見える実装に別々の設計理由がある」といった構造上の違いは、Lintや依存グラフだけでは捉えにくい。Code GrooveはGeminiが仮説を立て、コード・テスト・呼び出し関係・別の理由を調べ、根拠付きの意味イベントと設計上の懸念を提出します。

DTM型の画面にはディレクトリ階層、関数の演奏クリップ、実際に鳴るノートと伴奏が並びます。固定の音楽規則でジャズの旋律・和音・ベース・スウィングを作り、根拠のある懸念にだけリズムのずれた応答を加えます。気になる区間を選ぶと、該当するコードの行とAgentの理由が同じ画面に開きます。責務別のThemeと実装順のRepoは同じ意味イベント・音源を保ち、配置を比較できます。音だけを品質判定にせず、判断保留や理由のある違いも示します。

Google Cloud Runでwebと非公開workerを実行し、Vertex経由のGemini API（Google Gen AI SDK）を使用します。Firebase Auth、Firestore、Cloud Storage、Cloud Tasks、Secret Managerを使用。Agentのツールはサーバーが管理する読み取り専用操作に限定し、対象コードは実行しません。所有権・期限・実行権・日次クォータ・トークン予約・停止スイッチで自律性を制御します。

GitHub: https://github.com/kdoai/code-groove （非公開。ダッシュボードからGitHub Appで連携）

URL: https://code-groove-web-a5ygiois2a-an.a.run.app 。審査メールは `reviewer@example.invalid`。パスワードは管理者がSecret Managerから取得して、非公開の「動作確認の方法」欄へ記入してください。メール受信やソーシャルログインは不要です。

動作確認：初回の実画面デモ → A改善前を全体再生 → 「懸念の前後を聴く」 → オレンジの区間からコード・仮の仕様変更・別の設計理由を確認 → 「根拠の音だけ」で伴奏を外す → B改善後を比較。比較例は動作が一致する151行・116行のコードです。Agentの実行記録から実際の読み取り・仮説・反証を閲覧でき、質問欄は常に表示されます。保存された実解析４例の再生・根拠確認はAI呼び出し0件です。新しい調査はログインして「このサンプルを実解析」。審査アカウントのRepository画面には保存済み作業も表示されます。更新は変更箇所と影響する呼び出し元を調べ、同じスナップショットは索引・解析を再利用します。

構成図: `artifacts/architecture.png`（編集元 `docs/architecture.svg`）。シーケンス・DFD・音楽化の図と技術スタックは `docs/TECHNICAL_GUIDE.md`。３分デモ: `artifacts/code-groove-demo.mp4`。字幕付きの実画面録画で、音声は同じPCM音源・楽譜から、再生位置と伴奏の切替を含め収録タイミングに合わせて再構成します。ナレーションはありません。配信用MP4と再生成スクリプトをGit管理し、収録元の生動画・音声は除外しています。

```powershell
node scripts/capture-demo.mjs
uv run --with imageio-ffmpeg python scripts/assemble-demo.py
```

収録は公開サンプルだけを使い、新規AI呼び出しは0件です。再生成にはPlaywright Chromiumが必要です。
