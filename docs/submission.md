# 提出用ドラフト

**Code Groove — AIで増えたコードを、全体から聴く健康診断。**

AIによるコード生成に、人の全体読解が追いつきません。機能は動き、Lintやテストも通っていても、判断の置き場所・読み解く順序・将来の同時変更が負債になり得ます。Code Grooveは、そのような構造を理解する開発者とレビュー担当者のためのワークスペースです。対象スナップショット全体の索引から、Geminiが関連実装・呼出し・契約・テスト・別の説明を調べます。初回に見つけられた懸念を隠したり、能力を落として音の必要性を演出したりしません。

音楽は全体の責務を探索する入口です。同じ役割には同じ旋律とリズムを割り当て、実装の場所順と意味で揃えた配置を聴き比べます。離れたファイルで同じ旋律が戻る、１関数に複数の役割が交差する、といった観察から人が区間を選びます。繰返しや分離そのものを悪いとは判定しません。Geminiがその選択からコードを読み直し、将来の変更・読解負担と、分離を残す理由を精密検査します。経過観察、正当な境界、判断材料不足も有効な結果です。

DTM型の１画面にディレクトリ階層、ファイル・関数クリップ、実際に鳴るノート、低音・和音、大きいコード表示、常設のAgent質問欄を配置します。実ノートからコード行に戻れます。色は役割を識別し、健康の点数にはしません。音は固定の6モチーフ、4/4・96 BPM、スウィング、休符、ジャズの声部進行で編曲し、ドラムは使いません。初回は配置の演奏、確認後は根拠付きの固定応答を加えられます。伴奏は音楽の土台として明示します。

初期サンプルは、正常に動くチェックアウト機能の6ファイル・13索引関数です。ブラウザのオフライン試算と、サーバーの確定計算には正当な境界があります。一方、請求とポイントで将来キャンペーンの変更をどう共有するかは、人が所有契約と抽象化の代償を検討する問いです。最初から改善後を用意しません。公開データは実際の初回Gemini健診を保存したもので、初回の粗い責務分類もそのまま記録します。模擬・保存済み実解析・今の実解析は明示します。

精密検査の結果を人が確認して演奏へ反映することと、コードを変更することは別の操作です。改善が妥当ならGeminiに新しい差分案を依頼し、理由・代償・未実施の確認を読んで採用または却下します。採用後に別のスナップショットを独立して再健診し、初めて変更前後を聴き比べます。元コードは保存し、GitHubへの書込みや対象コードの実行はしません。懸念の撤回にも、元の対象関数すべての新しい読取根拠が必要です。

Cloud Runでwebと非公開workerを実行し、Google Cloud経由のGemini APIとGoogle Gen AI SDKのツールループを使います。Firebase Auth、Firestore、Cloud Storage、Cloud Tasks、Secret Managerを使用。Agentの操作はサーバー管理の読取・仮説・検証済み差分提出に限定し、所有権・期限・日次クォータ・トークン予約・停止で制御します。GitHub Actionsは変更に関連する検査を選択し、WIFと検証済みコミットで配備します。同じ検証済みSHAの配備に全スイートを重ねません。

Cloud Runは最小0、web最大2、worker最大1。常時稼働のVMやDBサーバーは使いません。AIを除く月6,000円の予算通知を設定しています。通知は請求の強制上限ではありません。AIも日次予約・件数・時間・出力上限で制御します。保存結果の再生はAI呼出し0件。同じソース・索引・モデル・プロンプトの更新は再利用し、変更がある場合は影響範囲を再検査します。

GitHub: [kdoai/code-groove](https://github.com/kdoai/code-groove)（非公開。提出ダッシュボードでGitHub App連携が必要）

URL: [Code Groove](https://code-groove-web-a5ygiois2a-an.a.run.app)。審査メールは `reviewer@example.invalid`。メール受信・ソーシャルログイン不要です。管理者がSecret Managerの `reviewer-password-placeholder` からパスワードを取得し、非公開の動作確認欄に記入します。Git・公開説明・動画には載せません。

動作確認：初回の実画面案内 → サンプルの全体または区間を再生 → 気になる音を選ぶ → 初回健診の候補も確認 → ログインして精密検査 → 根拠と正当な境界を確認 → 必要なら演奏に反映 → 経過観察または改善案依頼 → 差分を採用・却下 → 採用後だけ独立した再健診と比較。公開サンプルの保存済み質問は追加モデル呼出し0件で、新規検査とは区別されます。

同じ保存済み健診・音楽規則・音源なら、楽譜ハッシュと発音タイミングを再現します。Geminiを再実行した際の判断や物理的なスピーカー出力まで同一とは約束しません。音が文章・図より優れるか、将来負債を早く察知できるかは検証すべき仮説です。Lint・バグレビュー・動作確認を置換せず、音から根拠をたどる体験の実用性を評価します。
